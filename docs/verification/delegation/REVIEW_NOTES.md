# Coordinator review notes for the first integration

These observations concern in-progress worker code. Recheck the final patches rather than assuming they remain defects.

1. **Mock navigation egress:** designer-library's `packages/core/src/mocks.ts` currently sets `allow-scripts` with a CSP that blocks resource/connection loads. `packages/daemon/src/mocks.ts`'s `GUARD` only intercepts anchor clicks, forms and `window.open`. An arbitrary mock script can still assign its own frame's `location` or invoke `location.replace`, including an obfuscated remote URL. Frame sandboxing without top-navigation restrictions on the child itself does not prevent its own navigation. Do not claim zero network egress from these string guards. Implement an actual host-enforced navigation barrier for previews or an equally strong runtime boundary, preserving useful interactive mocks; test script-driven frame navigation and untrusted click handlers in a real browser/native host. Track any unverified browser behavior explicitly.

2. **Mock capture race:** `DesignMocks.capture` validates/lints file contents, computes hashes, then rereads each path in `putBlob`. A running design agent can change content or replace a validated regular file with a symlink between validation and that second read. This can persist unvalidated/secret content, even if later blob hash checks prevent preview. Capture one verified bounded snapshot from opened files, retain those buffers through lint/hash/store, reject symlink/path races and ensure recorded hashes correspond to the exact bytes stored. Add a meaningful regression test, not just an assertion that symlink names are rejected before the race.

3. **Stable project context:** One Answer originally derives a generated note directory from project display name. Independent projects with the same display name and a shared selected vault need distinct stable project namespaces and project-bound retrieval. Check against the new native registry identity, including migration of an existing owned generated folder without overwriting unrelated notes.

4. **Subscription cost state:** reported subscription plus unknown overage is insufficient for app auto-dispatch until that app user gives a durable explicit account-off attestation. The owner's Cursor worker approval in this development conversation only authorizes these workers. Unknown billing must still block, and attestation must not silently survive a change to provider/account connection.

5. **Runtime validation:** include actual Node 24/installed strip-only daemon execution, offline Rust checks and rendered native checks where available. Vitest transpilation cannot catch unsupported strip-only TypeScript syntax. A green fixture test is not proof of a live provider, real database container or phone connection.

6. **Compose approval content:** projects-docker's current `EnvironmentWorkbench.request/resolve` hashes argv and rechecks that the binding produces the same argv. Editing a Compose file's image, command, privileges, host mount, environment or published ports leaves argv unchanged, so that check does not invalidate the approved action. Bind the approval to the actual reviewed Compose/Dockerfile/config content and relevant resolved service settings, not only filenames. Execute from a validated immutable snapshot or otherwise close the check/use race. Test changed Compose content with unchanged filename/argv, including an unsafe mount or service command; ensure it is refused before a Docker subprocess launches. Preserve project ownership and explicit external pull/build permission.

7. **Project checks and Git hooks:** workflow-review's current `postMergeChecks` calls `runChecks` in a host scratch worktree and labels it `env: local`. The confirmed product requirement puts project apps/tests/tools in Docker. Route real project checks through the configured project container and show unavailable honestly; offline test fixtures can explicitly use disposable host execution. `performMerge` currently runs user hooks intact, including in a scratch worktree. Assess hooks/filters/fsmonitor/global Git configuration as executable code and potential hidden outbound actions. Merge approval must not silently authorize a deploy/push/migration hook. Preserve intended checks as explicit reviewed steps, disable or separately approve untrusted hooks for app-owned Git operations, and test with a harmless hook side-effect fixture. Record any unavoidable native-Git trust boundary visibly in preflight and security docs.
