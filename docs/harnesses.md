# Agent runtimes and decision advice

Subscription agents use their provider's official CLI and login. API-key and Ollama agents use the implemented `opencode-server` adapter by default. LM Studio remains blocked in this adapter because its tool capability contract has not been verified; the shared catalog may still list that configuration until the parent applies the display/preflight snippet in [integration notes](adapter-protocols.md). One Connect does not install OpenCode, sign in to vendors, pull models, or convert subscription credentials into API keys. Metered agent configuration and subscription overage remain subject to the existing human cost decisions.

The adapter protocols below were checked against public primary documentation and source on **2026-10-07**. Synthetic loopback contract tests exercise the bridge and daemon. No real OpenCode binary, Ollama inference, TypeSafe request, vendor installation or paid usage was performed for this verification. Protocol inspection and fixture tests do not establish live provider compatibility.

## OpenCode

The adapter accepts exactly **OpenCode 1.18.35**, the inspected [official release](https://github.com/anomalyco/opencode/releases/tag/v1.18.35). `SUPPORTED_SERIES` reports `1.18` for the catalog; `SUPPORTED_VERSIONS` controls acceptance of the exact patch. Other patches, development builds, unknown versions and `ACC_OPENCODE_SUPPORTED` overrides are refused. The bridge checks `--version` before starting `serve`, checks the runtime health version, and requires the operations in `/doc` before sending a prompt. The local bridge line protocol is `opencode-server/2`.

The [server overview](https://opencode.ai/docs/server/) documents loopback `serve`, HTTP Basic authentication, `/global/health`, `/event`, sessions and asynchronous prompts. For permissions and questions, the [tagged generated SDK](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/sdk/js/src/v2/gen/sdk.gen.ts) and [wire types](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/sdk/js/src/v2/gen/types.gen.ts) are authoritative: the current permission reply is `POST /permission/{requestID}/reply` with `{ "reply": "once" | "reject" }`. The overview still lists a legacy session permission route; the adapter does not use or fall back to it. Question replies use `POST /question/{requestID}/reply` with `{ "answers": string[][] }`; rejection uses `/question/{requestID}/reject`.

Each run starts an authenticated server at `127.0.0.1` on an ephemeral port in its assigned worktree. Its random password is passed only in the environment. Provider config references `{env:NAME}`; the server receives only the selected provider key and an explicit system-environment allowlist. Inherited provider keys, npm credentials, telemetry settings, proxies, `NODE_OPTIONS`, and OpenCode overrides are not forwarded. HTTP redirects are refused.

Config, home, cache and state are isolated per run; XDG data is private to the agent so saved sessions can resume. Project config, external/default plugins, external skills, Claude config, model catalog fetching, FFF, auto-update and LSP downloads are disabled; sharing, LSP and formatting are disabled in config. Home and managed-directory overrides are verified implementation controls from [Global](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/core/src/global.ts), [config paths](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/opencode/src/config/paths.ts), [flags](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/core/src/flag/flag.ts), and [runtime flags](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/opencode/src/effect/runtime-flags.ts). macOS managed preference files cannot be isolated by those flags, so their presence blocks startup. See the [managed-config implementation](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/opencode/src/config/managed.ts).

Download prevention needs more than disabling plugins. The inspected [provider implementation](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/opencode/src/provider/provider.ts) bundles the Anthropic, OpenAI, OpenAI-compatible and OpenRouter SDKs used here; an unbundled SDK would call `Npm.add`. Separately, [config loading](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/opencode/src/config/config.ts) starts a background dependency install. Its [npm implementation](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/core/src/npm.ts) uses [npm configuration](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/core/src/npm-config.ts), so the adapter enforces offline mode, an isolated empty npm cache/config, disabled scripts and a loopback registry. Missing optional config dependencies can produce an honest offline warning; they are not downloaded or represented as installed. OpenCode's [ripgrep resolver](https://github.com/anomalyco/opencode/blob/v1.18.35/packages/core/src/ripgrep/binary.ts) otherwise downloads a binary, so an existing executable `rg` on PATH is required before startup.

The bridge subscribes to SSE before sending a prompt, reconstructs `message.part.delta` text and reasoning, and records completed messages, tools, reported usage, errors and child sessions. It de-duplicates event IDs and terminal updates. The v1 event bus provides no replay cursor; an interrupted or malformed stream fails the run instead of reconnecting and pretending nothing was lost. A served model mismatch fails the run. Missing token counts and missing bash exit codes never become zero usage or a passed command.

Permission requests enter One Connect's existing policy and human approvals, then receive a single-use reply after the inbox decision. Pattern scopes are not treated as concrete commands or file paths; ambiguous scopes and unknown permissions require human review. Read-only tools are allowed; other capabilities default to asking. Single-answer questions reach the human inbox. A failed question reply or rejection ends the run with its cause and never claims the delivery succeeded. Native multiple-selection questions are currently rejected explicitly because the inbox cannot represent their answer shape. Pause and stop abort the session; resume uses the agent's saved session. No advisory result can substitute for a human approval.

## Ollama

Both native and compatible endpoints are documented by Ollama: [authentication](https://docs.ollama.com/api/authentication), [cloud access](https://docs.ollama.com/cloud), [OpenAI compatibility](https://docs.ollama.com/api/openai-compatibility), [model listing](https://docs.ollama.com/api/tags), and [model details](https://docs.ollama.com/api-reference/show-model-details).

| Configured route | Model endpoint | Authentication and selection |
|---|---|---|
| `provider: ollama` | Loopback daemon, default `http://127.0.0.1:11434/v1` | No provider key. Only installed, verified tool-capable local models are selectable. |
| `provider: ollama-cloud`, `ollama_route: daemon` | The configured loopback daemon's `/v1` | The daemon manages cloud sign-in. Use an available cloud alias returned by that daemon; One Connect does not pull it. |
| `provider: ollama-cloud`, `ollama_route: api` | Exactly `https://ollama.com/v1` | Bearer key from the `ollama-cloud` connection. Use the exact ID from the cloud `/api/tags` catalog. No local Ollama installation is needed for this route. |

Direct cloud `/api/chat` and compatible `/v1/chat/completions` are documented. Direct catalog names such as `gemma4:31b` can differ from app/daemon aliases such as `gemma4:cloud`; the adapter never rewrites one into the other. Cloud detection also examines `remote_model` and `remote_host`, so renamed remote aliases cannot accidentally be selected as local. These metadata fields and `POST /api/me` identity inspection are verified from the official [Go API types](https://github.com/ollama/ollama/blob/main/api/types.go) and [client](https://github.com/ollama/ollama/blob/main/api/client.go).

Probes only list models, inspect identity/version and inspect model metadata. The cloud catalog is public and is requested without a key; a successful catalog response is not proof that a stored key works. Missing identity, an unsupported identity endpoint, absent/malformed tool metadata or a rejected metadata probe stay unknown and make the model unselectable. The bridge repeats Ollama model/auth/route checks before starting a coding prompt, including explicitly selected models. Cloud model prices and remaining quota are not inferred from catalog data or presented as zero. The product's subscription usage remains unknown in this adapter; no paid validation request is made to fill that gap.

## Jev / TypeSafe System One

Jev is implemented as human-only decision advice, disabled by default. Its verified [official API reference](https://docs.typesafe.ai/api) specifies `POST https://api.typesafe.ai/v1/systemone`, Bearer authentication, and a JSON body with `state`, `model` and a named `questions` map. The adapter uses `jev-latest` and one `choice` question with a `criteria` map. Responses require `model`, the matching typed answer under `answers.decision`, its `choice`, probability distribution and confidence, plus integer token usage. The old flat `question`/`choices` request and `answer`/`model_version` response are not accepted. System One does not supply a prose rationale in this contract; the adapter leaves it empty.

Enabling requires explicit human cost, network and data confirmation for the exact host plus a stored `jev` key. Every request previews its bounded, redacted evidence and exact System One request body, hashes that body, and requires fresh confirmation for the matching hash. Stable option IDs avoid redaction/truncation collisions. Evidence discriminates merge, cost, settings and release/inspection/rollback actions; merge branch fields are read only for merge actions. Full bounded SHAs and action revision hashes participate in invalidation. Unknown action kinds fail closed.

Typed answers, selected options, probability distributions, confidence, model and usage are validated before any advisory is recorded. Responses are consumed up to 64 KiB; oversized or interrupted responses are refused without recording advice. A closed decision, changed evidence, disabled connection or changed endpoint during the request prevents recording a stale response. Advisory metadata stays separate from agent suggestions, human answers and approval records. Existing advice is invalidated when its evidence changes, and the `jev` actor remains refused by human answer paths. No TypeSafe request was made during this protocol repair.
