name: forms-navigation-data
description: "Use when designing forms, navigation, tables, lists and charts so they stay clear, accessible and complete across states."
---

**Forms**
- One column for most forms. Visible labels above fields; help text below for format or purpose; placeholders only as examples.
- Group related fields with a heading. Mark required fields, or mark optional ones when most are required — never both.
- Errors say what happened and how to fix it, next to the field. Keep what people typed.
- Use the right control: a switch for instant settings, a checkbox for choices submitted later, radio buttons for up to about five visible options, a dropdown for longer lists.
- One primary action, labelled with a verb (“Create project”). Secondary actions are visibly quieter.

**Navigation**
- Up to five top-level destinations in a top bar; a sidebar for more or for apps with sections. Mark the current page.
- Tabs switch views of the same thing; don’t use them for steps. Breadcrumbs or a back link for depth.
- On phones, navigation wraps or moves below the brand; keep every destination reachable.

**Tables and lists**
- Tables compare items across the same columns: a caption, short headers, left-aligned text, right-aligned numbers, and few columns on phones.
- Lists suit items read one at a time. Offer search and filters when a list grows beyond a screen; add pagination for long data.

**Charts**
- Bar charts compare categories, line charts show change over time, donuts show parts of a whole with few segments. Label axes or values; never rely on color alone; give every chart a text label summarizing it.

**Every data view designs its states:** empty (what will appear and the first action), loading (stable layout), error (what failed and how to retry), partial data, no permission and offline where relevant.
