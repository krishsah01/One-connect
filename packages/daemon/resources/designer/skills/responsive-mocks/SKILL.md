---
name: responsive-mocks
description: Build interactive, responsive local HTML mocks with real content and complete user-flow states.
---

Use the project design contract. Produce self-contained HTML/CSS/JavaScript in allowed paths; keep remote scripts, fonts, analytics and production data out of mocks. Include plausible project-specific copy, a useful primary flow, and empty/loading/error states. Test narrow and desktop widths, long labels, keyboard navigation and reduced motion. Make the artifact editable and explain which behavior is simulated. A mock is not a shipped feature or passing acceptance test. Capture real preview evidence before handing it off.
